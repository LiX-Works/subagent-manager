# 子代理委派与验收

主代理对任务与最终交付负责。只有子任务有明确边界、可形成有用且可验收的成果，且委派的收益足以覆盖交接成本时才调用子代理。授权使用子代理不是要求每次都使用，也不以代理数量为目标。

## 选择与交接

- 先确定子任务需要什么材料、工具与判断能力，再按[选择因素](references/model-selection.md)决定由主代理、原生子代理或外部 CLI 完成。不同环境提供的工具、模型、档位和配额不同，不能依赖仓库中的固定名称推定可用。需要具体档位写法时可查看[可选模型配置示例](references/native-models.md)；用户未采用的示例不自动生效。
- 需要连续使用当前 Codex 已配置的工具和项目上下文时，优先考虑实际具备这些能力的原生代理。输入已经备齐、任务可以独立完成时，可考虑外部 CLI；它不自动继承 Codex 的 Skill 与 MCP。[外部 CLI 交接](references/external-cli.md)按需读取。
- 委派时说明目标、必要材料、可写范围、完成标准和返回位置。若任务要求特定模型或思考强度，应在实际工具参数中显式指定；不以提示词或隐式继承冒充已选择。组合不可用时说明限制并调整任务分配。

## 协调与验收

- 多代理并行时协调文件或模块责任，避免未协调地同时修改同一文件。需要隔离时使用独立工作目录或工作树；顺序子任务也可委派。
- 主代理核对关键来源、可执行结果、测试与限制。模型自信、多个模型一致或退出码 0 都不能代替证据；不必机械重做子代理全部推理，但无法核验的重要结论应保留不确定性。
- 依赖 CLI、MCP 或工具出错时先做有限排查，检查入口、连接和具体错误；能由主代理接手或换已授权路径就继续。仍不可用时停止受影响委派，若关键目标无法可靠完成则暂停相关部分，否则继续可完成的工作并在结束时报告。不为普通排错擅自更改认证、付费或全局环境。

子代理不自动获得额外发布、登录、付费或读取私有材料的授权。使用外部服务前按当前用户的实际许可和额度行事，不复制认证文件或建立绕过限制的账号轮换。个人模型排序、预算阈值和平台排除项不由本 Skill 预设。
