# 代理与模型选择因素

选择不是固定排行榜。先判断任务是否适合委派，再比较以下因素：

| 因素 | 要问的问题 |
|---|---|
| 工具可达性 | 子代理是否能直接使用本任务所需的文件、搜索入口、MCP 和 Skill？ |
| 独立性 | 输入能否一次交齐，还是主代理需要持续代跑工具、搬运上下文？ |
| 难度与错误代价 | 是否有关键推理、难以复核的结论或高风险操作？ |
| 时间与额度 | 委派能节省多少时间，当前用户允许使用哪些模型和额度？ |
| 验收方式 | 能否用原文、测试、可执行结果或清晰的证据链检查交付？ |

原生 Codex 子代理通常更容易衔接当前项目与本会话实际暴露的工具，但也不能假定它必定继承每项能力。外部 CLI 可以独立分析准备好的材料，或提供特定平台/模型能力；它有自己的工具环境，不自动共享 Codex 配置。困难部分可以直接交给更合适的模型，不强制先让便宜模型试错。

模型和推理档位以本轮工具 schema 与账户能力为准。若已决定特定组合，要在启动参数中传入并在可能时核对实际记录；不能因为主代理恰好使用某模型，就让子代理无意继承。个人最小档位和预算可以另行设置，但不是这份公共 Skill 的通用要求。
