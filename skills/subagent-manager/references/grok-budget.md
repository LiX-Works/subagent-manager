# Grok日常使用、额度查询与日预算

## 日常原则

本方案鼓励在有研究价值的任务中调用Grok，并允许有目标地深入连续查询，不以尽可能省额度为目标。有重要缺口就继续追查；不因尚未达到的额度阈值而预先削减必要工作。优先追原始来源、回复/引用、时间线、多方观点与反例，主代理仍核验关键来源和适用条件。简单事实可直接解决，资料充分且后续主要重复时收束。

已验证的TUI`/usage`查询没有触发模型调用；若改为向模型发自然语言问题，可能消耗套餐额度。只用已授权免费或套餐额度；未经使用者明确授权，不启用按量API、额外购买或自动充值。

## 日预算阈值

本示例按**Asia/Shanghai自然日消耗的整周总额度比例**执行，跨项目累计，不是本任务或整周已用量。使用其他时区的人应调整日界线与下方账本脚本，而不是直接套用本例。

| 当日消耗 | 行为 |
|---|---|
| 1/7（14.29个百分点） | 检查进度/消耗与低效重复，按效果调整任务组织，不停工、不自动缩减必要研究或降低思考 |
| 1.5/7（21.43个百分点） | 完成当前有边界任务后提醒；告知后可在已有授权范围继续，提醒本身不是审批或停工，无须等待回复 |
| 2/7（28.57个百分点） | 标记过量，默认建议不再新派Grok，保留成果由用户决定是否继续 |

这些阈值是一套可改的个人预算示例；2/7后不派新任务是可覆盖的保守执行默认，不冒称永久硬停机。实际限额或认证失败停止失败路径，不自动换号绕限制。

2/7默认只限制继续派发Grok，不强杀当前任务，也不停止主代理或其他渠道的独立工作；用户可明确调整这个暂定策略。

## 频率（可调整默认）

当天首次派发Grok任务前记可信基线。原则上每完成一个有边界的Grok子任务查一次`/usage`并记录；同一问题的连续搜索、追问和复核算一个子任务，在该子任务收束时查，不逐条查询。大型深度任务在开始前也查；接近阈值，或已知其他项目在上次快照后使用了Grok时，再次派发前刷新。非Grok工作不触发查询；主任务结束时若最近一次Grok子任务已查且此后无新使用，不重复查。无任务不定时轮询，同一阶段无新消耗不重复提醒。已有可靠额度入口，不因担心查询成本放弃必要检查。

**已验证的首选查询：**在能操作交互终端时，启动已登录的`grok --no-alt-screen --minimal`，待界面就绪后输入`/usage`，读取`Weekly limit`百分比和`Next reset`，然后用`/quit`退出。2026-09-27在Grok Build 1.0.40和1.0.41上，同会话重复及新会话查询均返回账户额度信息，测试会话没有模型调用。可用脚本驱动交互终端来读取，但这仍依赖界面文字；本仓库没有提供或验收独立的结构化额度接口。CLI参数和页面可能随版本变化，先核对当前help。界面的整数百分比可能有舍入，接近预算阈值时不要据此声称精确到小数位。若终端不可交互，可用官方网页Settings → Usage。官方入口：[Grok使用量说明](https://docs.x.ai/grok/faq)、[终端命令](https://docs.x.ai/build/modes-and-commands)。

若采用自然语言向Grok提问，可直接发简短请求，不要求零消耗；但只有回答明确对应实际账户界面/受支持接口的可核对数据时才记为余额。单纯模型估算不算验证。`grok usage <session>`在本机help中被定义为**会话Token和成本**；`grok -p "/usage"`未作为账户额度命令验收。

只记录真实账户界面、受支持接口或可信用户反馈的数据。模型回复给出百分比但没有可核对的实际来源时仍标unknown；不能用会话Token/美元反推精确比例。合理尝试后说明一次监控缺口，已有授权内研究可继续，不为寻找零消耗办法反复排错；若确实无法判断一个大型持续任务是否会超出已有预算，再取得用户预算或可信快照。

## 计算与共享

同周期当日首个可信剩余百分比减最新值=观察消耗。首次采样若非日初只是下界；跨日新基线。跨周重置先累计已观测旧段，再记新段，不允许负消耗或把全天已经消耗清零。余额异常上升标待核实。

[quota-ledger.py](../scripts/quota-ledger.py)记录人工或受支持接口取得的快照，**不查询账户、不调用Grok、不自动提醒**。默认写入`%LOCALAPPDATA%/subagent-manager/grok-quota/`（其他系统用用户数据目录），可通过`--state-dir`改位置。脚本用文件锁防并发覆盖。只用账号标签1等，不存邮箱、token或账单原文。若界面显示“已用百分比”，记录前先换算成`100 - 已用百分比`的“剩余百分比”。

```powershell
python '<已安装Skill目录>/scripts/quota-ledger.py' record --account 1 --remaining 82 --period '已核实的重置周期标识' --source 'user-/usage'
python '<已安装Skill目录>/scripts/quota-ledger.py' status --account 1
```

period是非敏感重置时间/周期标识，不随任务变化，不知道就不造数据。observed_daily_pp始终按观察下界解释；tier按下界判断，可能低估全天。跨周期、首样或跨日未采样窗口有gap提示。脚本按UTC+8日期计算。

交互终端查询已在上述版本验收；仍未建立独立的无交互结构化余额接口或定时监控。无需读取认证文件。没有可信快照就无有效阈值判断，不能把会话成本或模型猜测记到账本。
